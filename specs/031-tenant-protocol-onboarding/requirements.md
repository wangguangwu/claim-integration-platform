# 031 多租户协议流水线接入与网关租户限流（MVP）

## 1. 背景与目标

理赔申请签收入口已按 `tenantCode + protocolVersion` 路由到租户协议流水线，但当前只有租户 A 的完整适配实现，租户 B 已于此前删除。实际需要接入人保健康、新华保险、太平洋保险、平安保险、泰康保险、永诚保险六个租户；在真实协议尚未提供前，六个租户先使用平台标准签收报文，每个租户仍保有独立流水线。验签与解密保留可替换的空实现，流水线必须将标准报文转换为标准受理命令。同时网关签收接口目前只配置了 `tenant-a` 的租户配额，需要改为六个实际租户分别限流。

目标：

- 六个租户各注册一条独立协议流水线，按租户编码与协议版本路由。
- 流水线执行空验签、明文解密、标准报文解析和校验，产出标准受理命令。
- 删除租户 A 遗留适配、旧默认流水线、旧五阶段组件与租户 A 请求 DTO。
- 网关签收接口按六个租户分别配置限流阈值，移除 `tenant-a` 配额。
- 不改变注册中心契约、签收入口、领域模型、数据库与消息链路。

## 2. 业务规则

1. 租户身份由请求头 `X-Tenant-Code` 与 `X-Protocol-Version` 共同确定，两者都必须精确匹配流水线声明值。
2. 本次接入的租户编码固定为 `PICCLIFE`、`XINHUA`、`CPIC`、`PINGAN`、`TAIKANG`、`YONGCHONG`，协议版本固定为 `v1`。
3. 每个租户在 `interfaces/web/tenantprotocol/tenants/<租户编码小写>` 下拥有独立流水线类，并以 Spring Bean 注册；不得共用同一条流水线实例。
4. 每条流水线固定按“验签 → 解密 → 标准报文解析与校验 → 命令转换”执行。默认验签只记录 INFO 日志后放行，默认解密只记录 INFO 日志并原样返回报文；两者均不得输出请求正文、签名、密钥或证件号。
5. 标准报文使用平台标准字段：`externalClaimApplicationNo`、可选 `claimApplicationNo`、四个角色人员（`applicant`、`primaryInsured`、`accidentPerson`、`payee`）及 `materials`。人员字段为 `name`、`gender`、`certificateType`、`certificateNo`，材料字段为 `materialType`、`originalFileUrl`。
6. 注册中心行为保持不变：同一租户与协议版本只能匹配一条流水线；无匹配时返回“未找到匹配的租户申请协议流水线”；流水线返回空命令或租户编码不一致时返回“租户申请协议转换结果无效”。
7. 每条流水线必须记录一条包含租户中文名称、租户编码与协议版本的 INFO 日志，并产出 `tenantCode` 与当前上下文一致的 `ClaimApplicationIntakeCommand`；报文非法或字段不满足标准模型约束时拒绝请求。
8. 删除租户 A 的适配包、请求 DTO、旧默认流水线实现与旧五阶段包；保留 `TenantProtocolPipeline` 契约与 `TenantProtocolPipelineRegistry`。
9. 网关签收接口 `claim-application-intake` 按六个租户分别配置单节点 QPS，默认均为 20，可通过环境变量按租户独立覆盖；路由兜底阈值保持 50。
10. 租户配额必须在 1 与路由兜底阈值之间；配置非法时网关启动失败，不得静默忽略。
11. 租户配额只作用于签收接口；同一租户的其他接口只受路由兜底约束。
12. 缺少租户请求头的请求仍由网关在限流之前以 400 拒绝。

## 3. 正常场景

- 携带 `X-Tenant-Code: PICCLIFE`、`X-Protocol-Version: v1` 与合法标准报文调用签收接口：网关校验请求头并通过租户配额，应用服务写入租户上下文，注册中心命中人保健康流水线；空验签、明文解密、标准报文转换后进入签收用例。
- 新华保险、太平洋保险、平安保险、泰康保险、永诚保险请求按同一链路命中各自流水线并完成标准签收。
- 单个租户请求量未超过其配额：请求进入应用服务并命中对应流水线。
- 单个租户请求量超过其配额：网关返回 HTTP 429，请求不进入应用服务，不产生流水线日志。
- 不同租户各自消耗配额，一个租户被限流不影响其他租户。
- 网关启动时加载 1 条路由兜底规则与 6 条租户配额规则。

## 4. 异常场景

- 同一租户与协议版本注册了两条流水线：注册中心返回“租户申请协议转换结果无效”之外的配置冲突异常，请求失败。
- 租户编码或协议版本无法匹配任何流水线：注册中心返回“未找到匹配的租户申请协议流水线”。
- 标准报文为空、不是 JSON 对象或字段不满足标准模型约束：流水线返回明确业务异常，不进入签收用例。
- 租户配额小于等于 0 或大于兜底阈值：网关启动时抛出异常并终止启动。
- 请求正文不可解析或包含敏感信息：流水线只用于转换，日志中不得出现报文内容、签名、密钥或证件号。

## 5. 边界条件

- 租户编码区分大小写：`picclife` 不会匹配 `PICCLIFE`。
- 协议版本不是 `v1`：不匹配任何流水线，按未找到流水线处理。
- 已删除的 `tenant-a`：网关允许通过（只受兜底配额约束），应用服务因无匹配流水线返回业务失败。
- `claimApplicationNo` 缺失或全为空白时按首次签收处理。
- 同一租户在不同接口上的配额互不影响。
- 租户配额等于兜底阈值时仍合法。

## 6. 本次范围

- `claim-application-service` 新增标准报文转换、默认验签/解密和六个租户流水线包及包说明。
- `claim-application-service` 删除租户 A 适配包、`TenantAIntakeRequest`、旧 `DefaultTenantProtocolPipeline` 与 `tenantprotocol/stage` 全部类。
- 更新 `tenantprotocol` 与 `pipeline` 包说明。
- `claim-gateway` 签收接口配置六个租户配额，移除 `tenant-a` 配额。
- 新增 031 三件套 Spec 与相应单元测试。

## 7. 非本次范围

- 不实现真实租户的验签、解密、租户私有报文解析、字段映射与错误映射。
- 不新增租户私有请求 DTO，不恢复旧的泛型五阶段组件与旧默认流水线。
- 不修改 `TenantProtocolPipeline` 契约、注册中心、签收入口、签收用例、领域模型、数据库与消息契约。
- 不调整路由兜底阈值、Sentinel 控制台配置与其他路由限流。
- 不改造现有测试与集成文档中的历史租户示例。

## 8. 验收标准

1. 六个租户编码分别命中各自流水线，并将合法标准报文转换为租户编码正确的标准受理命令。
2. 流水线、默认验签和默认解密日志不包含请求正文、签名、密钥、证件号或其他敏感报文内容。
3. 标准报文非法时返回明确业务异常；注册中心仍能在无匹配、重复匹配与空命令三种情况下返回既定业务异常。
4. `tenant_a` 包、`TenantAIntakeRequest`、`DefaultTenantProtocolPipeline` 与 `tenantprotocol/stage` 包不再存在，且代码中无残留引用。
5. 网关配置中不存在 `tenant-a` 租户配额，存在六个租户配额，默认值均为 20。
6. 网关启动日志显示 1 条路由兜底规则与 6 条租户配额规则。
7. 同一租户超额返回 HTTP 429，其他租户不受影响。
8. 标准命令转换与六租户路由单元测试通过，网关与理赔申请服务使用 JDK 21 编译通过。
