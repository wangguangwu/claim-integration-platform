# 项目背景与目标

## 功能目标

在不调整现有分层目录和业务代码的前提下，补齐包级职责说明与代码导航文档，使开发人员能按业务能力和分层职责快速定位源码。

## 业务规则

- 当前 DDD 分层目录保持不变，不移动包、不修改类名、不调整依赖方向。
- 包级说明必须明确职责、允许依赖和不应放置的内容。
- 代码导航必须覆盖签收、材料、承保、审核、问题件和异步集成的跨层目录映射。
- 导航说明必须以现有目录和实现为依据，不得新增业务链路或技术组件。

## 正常场景

- 开发人员可从根 README 进入代码导航文档。
- 开发人员进入 `claim-application-service` 的分层根包时，可通过 `package-info.java` 判断代码归属。
- 开发人员可按业务能力定位领域、用例、基础设施和入站入口目录。

## 异常场景与边界条件

- 预留模块和空目录只在导航中标识其当前定位，不将其描述为已实现能力。
- `shared` 仅允许存放跨业务复用能力，不能因导航文档新增而放宽目录边界。

## 本次范围

- 根 README 的文档入口。
- `claim-application-service` 根包及各分层根包的 `package-info.java`。
- 全仓代码导航文档。

## 非本次范围

- 业务能力优先的包迁移。
- 变更领域模型、接口、数据库、Redis、MQ 或第三方系统。
- 修改预留模块的实现范围。

## 验收标准

- README 可链接到代码导航文档。
- 7 个 `claim-application-service` 分层根包均有中文包级说明。
- 导航文档覆盖 6 条核心业务能力的跨层目录映射和常用排查路径。
- 全量 Maven 构建和现有测试通过。
