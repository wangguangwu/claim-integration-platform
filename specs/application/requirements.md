# Application 业务域需求

## 1. 定位

Application 承接外部理赔申请从接入到交付的完整链路，边界止于「审核系统成功接收申请并返回案件信息」。

同步链路只做租户协议转换、参数校验、幂等判断、signNo 生成和落库；影像处理、自动承保、审核交付全部异步执行。

## 2. 核心概念

| 概念 | 说明 |
| ---------------- | -------------------------------------------------------- |
| Application | 一次理赔申请，业务编号 signNo，本域聚合根 |
| 外部申请单号 | 租户侧单号，与 tenantCode 共同构成幂等键 |
| 影像材料 | 申请附带的影像文件，是进入受理的前提 |
| 承保结果 | 自动承保产出的承保结论 |
| 交付任务 | 向审核系统投递申请的动作及其结果 |
| 关联 Case | 审核系统受理后产生的案件，由 Case 业务域持有 |

一个 Application 可以关联多个 Case，Application 不持有 Case 数据，只通过 signNo 建立追溯关系。

## 3. 功能需求

### 3.1 外部申请接入（同步）

- 按 `tenantCode + protocolVersion` 选择 TenantAdapter，未注册的租户协议直接拒绝。
- Adapter 完成签名验签、解密、报文解析、字段映射和参数校验。
- 校验通过后以 `(tenantCode, externalRequestNo)` 判断幂等，重复请求直接返回首次生成的 signNo，不重复落库、不重复发起异步流程。
- 校验通过后生成全局唯一 signNo 并落库，初始状态为待受理。
- 同步响应只返回 signNo 与受理受理标识，不返回受理结果。
- 校验失败不落库，返回租户协议约定的错误码与错误描述。
- 报文、签名、解密失败需记录接入日志，不产生 Application。

### 3.2 影像处理（异步受理）

- 落库成功后投递受理消息，由影像处理链消费。
- 影像逐份下载、格式校验、转存到 FileStorage，并记录每份材料的处理状态。
- 全部影像处理成功即受理成功，Application 进入可承保状态。
- 任一影像处理失败即受理失败，停止后续流程，写入异常记录并保留已成功的材料结果。
- 受理失败允许重试，重试从失败影像继续，不重复处理已成功材料。
- 重试次数耗尽后转人工，不再自动推进。

### 3.3 自动承保

- 仅受理成功的 Application 进入自动承保。
- 承保规则判定产出承保结论：通过、拒保、转人工。
- 承保结论、命中规则和判定时间落库，可在详情页查询。
- 拒保结论不进入审核交付，直接结束并记录结束原因。

### 3.4 审核交付

- 承保通过后向审核系统交付申请。
- 交付失败按退避策略重试，重试期间状态保持交付中。
- 审核系统返回案件信息后完成签收，Application 进入签收完成。
- 交付请求报文、响应报文、返回码、耗时全部留痕，供问题排查与异常诊断使用。
- 交付成功后通过消息把案件信息交给 Case 业务域，Application 不直接写 Case 数据。

### 3.5 问题件与补材

- 影像或审核环节判定为问题件时，Application 进入待补材状态并记录问题原因、问题类型和补材要求。
- 补材到达后基于原 Application 重新进入影像处理，不新建申请。
- 补材次数与补材轮次需要记录。
- 问题件超过租户约定时限未补材的，按租户规则转人工或关闭。

### 3.6 申请撤销

- 待受理、受理失败、待补材状态允许撤销。
- 已交付审核系统后不允许自动撤销，只能人工处理。
- 撤销为终态，撤销后到达的异步消息一律拒绝并记录。
- 撤销需要记录操作人、原因和时间。

### 3.7 查询与轨迹

- 按 signNo 查询申请详情：基本信息、参数校验结果、影像材料、承保结果、审核交付结果、轨迹、异常、关联 Case。
- 每个处理节点写入一条轨迹记录，携带 traceId、节点、结果和耗时。
- 列表查询支持租户、状态、时间范围、外部单号、承保结论筛选。
- 异常记录可查询、可标记处理结果，不物理删除。

## 4. 状态需求

| 状态 | 含义 | 是否终态 |
| ------------------ | ---------------------------------- | -------- |
| 待受理 | 申请已落库，等待影像处理 | 否 |
| 受理中 | 影像处理执行中 | 否 |
| 受理成功 | 影像全部处理完成 | 否 |
| 受理失败 | 影像处理失败，等待重试或人工 | 否 |
| 承保中 | 自动承保执行中 | 否 |
| 承保完成 | 承保结论已产出 | 否 |
| 交付中 | 向审核系统投递中 | 否 |
| 待补材 | 问题件，等待租户补材 | 否 |
| 签收完成 | 审核系统已接收并返回案件信息 | 是 |
| 已拒保 | 自动承保拒保 | 是 |
| 已撤销 | 申请被撤销 | 是 |

状态只能由状态机推进，禁止通过直接改库、脚本或消息跳过中间状态。

## 5. 非功能需求

- 同步接入（不含租户侧加密设备耗时）P99 小于 500ms。
- 异步消息至少一次投递，消费端必须幂等。
- 同一 Application 的状态变更串行化，使用乐观锁防止并发覆盖。
- 全链路携带 traceId，轨迹、异常、外部调用记录均带 traceId。
- 租户数据隔离：所有查询、写入必须限定 tenantCode。
- 关键节点（签收、受理结果、承保结论、交付结果、撤销）写入审计日志。
- 影像文件通过 FileStorage 接口访问，业务代码不感知具体存储产品。

## 6. 不在本期范围

- 影像内容识别、OCR 结论与自动核赔
- 人工审核工作台与核赔规则维护界面
- 保费计算、退保、批改
- 与再保、财务系统的对接
