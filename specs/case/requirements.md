# Case 业务域需求

## 1. 定位

Case 承接案件进入平台后的规则判断、阶段编排、外部交付和回执处理。Case 由 Application 交付成功后的消息创建，通过 `sourceSignNo` 追溯来源申请。

## 2. 核心概念

| 概念 | 说明 |
| ------------ | -------------------------------------------------------------- |
| Case | 一个理赔案件，业务编号 caseNo，本域聚合根 |
| sourceSignNo | 来源申请编号，由 Application 提供，本域只读 |
| 阶段 | 案件处理单元，典型为报案、影像、理算 |
| 阶段 Handler | 单个阶段的执行逻辑，按阶段链顺序编排 |
| 同步阶段 | 外部调用返回即确认结果，随后推进下一阶段 |
| 异步阶段 | 提交后进入等待，收到回调后恢复阶段链 |
| 回执 | 外部系统对异步阶段提交的最终结果 |

## 3. 功能需求

### 3.1 案件接入

- 消费 `claim-application-delivered` 消息创建案件。
- 按消息中的案件信息生成 caseNo，保存 `sourceSignNo`、租户、协议版本和初始阶段。
- 消费幂等：同一消息重复投递只创建一次；同一 sourceSignNo 允许多个 Case（一申请多案件）。
- 建案后立即进入规则判断，不需要人工触发。

### 3.2 推送规则判断

- 按租户、险种、案件属性判断是否需要推送外部系统以及推送哪些阶段。
- 规则判定结果落库，包含命中的规则和阶段链。
- 判定为无需推送的案件直接结束，并记录结束原因。

### 3.3 阶段编排

- 阶段链按 `报案 → 影像 → 理算` 顺序执行，阶段链内容由规则判定产出，不写死。
- 同步阶段执行成功即推进下一阶段；执行失败进入重试或人工。
- 异步阶段提交成功后暂停执行，案件进入等待回调状态。
- 收到对应回调后恢复阶段链，从该阶段之后继续执行。
- 阶段执行必须校验当前阶段，重复推进、乱序推进一律拒绝。

### 3.4 外部交付

- 按 `tenantCode + protocolVersion` 选择 `TenantDeliveryAdapter`。
- Adapter 负责加解密、签名验签、报文转换、外部接口调用、返回码映射、回执解析。
- 同步阶段的实时结果与异步阶段的受理回执分别处理。
- 交付失败保留请求与响应报文，支持按阶段重新提交。

### 3.5 回调处理

- 接收外部系统的阶段回调，解析后校验归属案件与阶段。
- 回调幂等：同一回调重复到达只生效一次。
- 回调乱序或过期（案件已推进到后续阶段）时记录并丢弃，不回退状态。
- 回调成功推进阶段链；回调失败按失败处理策略进入重试或人工。

### 3.6 失败重试与恢复

- 同步阶段失败、异步回调失败、回调超时都需要可重试。
- 重试以阶段为最小单位，不重跑已完成阶段。
- 回调等待超时先做回执反查，反查无果再重投或转人工。
- 案件长时间停滞时由补偿任务按当前状态恢复。

### 3.7 轨迹与异常

- 每个阶段记录开始、提交、回调、结果，带耗时与 traceId。
- 每次外部调用记录请求、响应、返回码、耗时。
- 异常记录包含阶段、错误码、错误信息、重试次数和处理状态。
- 轨迹与异常只追加，不物理删除。

### 3.8 查询

- 按 caseNo 查询案件详情：基本信息、来源申请、当前阶段、阶段轨迹、外部调用、回执、重试记录、异常。
- 支持按租户、状态、当前阶段、sourceSignNo、时间范围查询列表。

## 4. 状态需求

| 状态 | 含义 | 是否终态 |
| ---------------- | -------------------------- | -------- |
| 待判断 | 已建案，等待规则判断 | 否 |
| 待执行 | 已确定阶段链，等待执行 | 否 |
| 阶段执行中 | 当前阶段执行中 | 否 |
| 等待回调 | 异步阶段已提交，等待回执 | 否 |
| 已完成 | 阶段链全部执行成功 | 是 |
| 已终止 | 规则判定无需推送或人工终止 | 是 |
| 已失败 | 重试耗尽或不可恢复错误 | 否（可人工恢复） |

## 5. 非功能需求

- 回调入口 P99 小于 300ms，回调内不做长耗时外部调用。
- 阶段执行与状态变更串行化：同一 caseNo 使用 Redis 锁 + 数据库乐观锁。
- 异步阶段等待回调必须有超时上限，不能无限等待。
- 所有外部调用必须设置连接与读取超时，禁止无超时调用。
- 全链路 traceId 透传到外部调用与回调处理。
- 租户数据隔离：所有查询、写入限定 tenantCode。
- 案件数据与 Application 数据分库，禁止跨库查询。

## 6. 不在本期范围

- 理算规则引擎与赔付计算
- 案件合并、拆分、注销
- 外部系统主动发起的案件查询
- 案件报表与统计分析
