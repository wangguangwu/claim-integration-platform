# 项目背景与目标

## 功能目标

在不改变异常对外行为的前提下，消除理赔申请服务中由 IDE 标记为可由 Lombok 生成的重复错误码访问器。

## 业务规则

- 三类业务异常仍必须对外提供名称和返回类型均为 `getErrorCode()` 的公共访问器。
- 异常构造、错误码赋值、异常消息和异常原因传递行为保持不变。
- 仅处理可由 Lombok 无语义差异生成的访问器；包含父类初始化、配置换算或派生资源初始化的显式构造器不在本次范围内。

## 正常场景

- 签收、异步和问题件异常均可正常读取对应错误码。

## 异常场景与边界条件

- 带原始异常原因的签收和问题件异常仍保留原始原因与错误码。
- Lombok 注解处理不可用时，构建应失败，不允许产生缺失访问器的运行产物。

## 本次范围

- `ClaimApplicationIntakeException`、`ClaimApplicationAsyncException`、`ClaimApplicationIssueException` 的错误码访问器。
- 本次重构的构建与回归验证。

## 非本次范围

- 改变业务异常模型、错误码或接口返回格式。
- 将含有业务初始化逻辑的构造器替换为 Lombok 构造器。
- 引入新的 Lombok 依赖或调整项目依赖版本。

## 验收标准

- 三类异常均可调用 `getErrorCode()` 并返回构造时传入的错误码。
- 带 `cause` 的异常仍可通过 `getCause()` 取得原始异常。
- 全量 Maven 构建和现有测试通过。
