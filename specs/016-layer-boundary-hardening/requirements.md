# 项目背景与目标

## 功能目标

补齐剩余关键入口与包级 JavaDoc，修正 HTTP 响应和问题件入站适配的目录归属，并用架构测试持续校验理赔申请服务的分层依赖方向。

## 业务规则

- 启动入口、协议流水线装配和网关环境初始化必须说明其业务职责或执行时序。
- 公共 HTTP 响应模型属于入站适配层；问题件 HTTP 接口属于问题件业务能力，不属于签收业务能力。
- 包移动不得改变 HTTP 路径、请求/响应字段、消息绑定、枚举值或业务状态机。
- 理赔申请服务必须遵循 `interfaces → usecase → domain ← infrastructure`：领域层不得依赖外层；用例层不得依赖入站适配或基础设施；基础设施不得反向依赖用例或入站适配；入站适配不得直接依赖基础设施。

## 正常场景

- 开发人员可从包路径直接识别公共 HTTP 协议模型和问题件 HTTP 入口的归属。
- 新增代码违反分层依赖方向时，Maven 测试阶段明确失败。
- 网关、租户和可观测性模块可从包级 JavaDoc 了解职责边界。

## 异常场景与边界条件

- 移动 Java 包后，已有调用方必须使用新包 import，避免遗留旧包引用。
- 包级文档只说明已有模块能力；案件和 AI 预留模块不得被描述为已实现完整业务能力。
- 架构测试仅验证申请服务分层，不限制模块外的依赖关系。

## 本次范围

- 剩余 10 个公开入口或组装方法的 JavaDoc。
- 网关、租户、可观测性、案件和 AI 模块的关键包级 JavaDoc。
- `ApiResponse` 与问题件 HTTP 接口的包归属调整。
- ArchUnit 架构测试与必要测试依赖。

## 非本次范围

- 将所有业务能力迁移为纵向切片目录。
- 修改 HTTP 路径、消息契约、数据库、Redis、MQ 或第三方系统行为。
- 实现案件或 AI 预留模块的业务能力。

## 验收标准

- 10 个剩余公开入口或组装方法均有中文 JavaDoc。
- `ApiResponse` 位于 `interfaces.web`，6 个问题件 HTTP 类位于 `interfaces.issue.web`，无旧包引用。
- 架构测试覆盖 4 条分层依赖规则并通过。
- 全量 Maven 构建和现有测试通过。
