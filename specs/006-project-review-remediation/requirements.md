# 006 全项目评审整改需求

## 功能目标

- 消除 2026-10-29 全项目只读评审确认的启动风险、错误语义缺陷、假件泄漏风险与不可定位的异步链路，使理赔申请服务在真实部署形态下可用、可运维、可排障。
- 收敛工程结构：后端只保留有真实职责的模块，删除仪式性空壳模块与零引用依赖，让"平台"的模块数与实际业务能力一致。
- 建立与"功能定稿前不保留单元测试"这一决定相匹配的替代验证机制，保证每轮改动都可在运行栈上重复验证。
- 本 Spec 不新增业务功能，不改变对外申请语义、状态机与持久化契约。

## 决策记录

- 2026-10-29 服务负责人批准：后端模块收敛为 `claim-foundation`（单模块）+ `claim-gateway` + `claim-application-service`，空壳的 `claim-case-service`、`claim-ai-service` 整模块删除、不留占位目录；本地联调假件从生产 jar 剥离为独立模块；单元测试继续不恢复，验证靠固化脚本走运行栈。
- 服务边界维持单进程：异步内核约 25 msg/s、承保领域仅约 91 行，均不构成拆分理由。材料处理域的拆分设置决策门——出现消息积压或同步受理 P99 被拖高时才启动拆分，本 Spec 不拆。
- 模块与目录形态改动遵循 AGENTS.md §9：先改本 Spec 与受影响的历史 Spec/文档，再改代码。

## 业务规则

- 运行时必需的配置不得只存在于某个 profile：调度间隔、批量、退避与滞留阈值在任何 profile 下都必须可解析；profile 文档只允许放本地覆盖项。
- 假件默认关闭：模拟开关在非联调形态下必须为关闭；外部系统地址不得默认指向本服务自身，缺失即启动失败并报出缺失配置键名。
- 外部系统契约路径属于配置：生产出站客户端不得内嵌联调假件的路径字面量。
- 业务异常必须保留原始原因：捕获后重新抛出时挂上 cause，禁止静默丢弃；日志禁止输出报文原文、证件号与密钥。
- 用户可感知的输入问题不得报成服务端故障：领域不变式失败与内部重试超限必须映射为明确的业务错误码，只有真正的服务端故障才返回 5xx。
- 业务异常与错误码全项目只有一套，落在 `shared/contract`，按域分段命名，同一语义不得有两个码。
- 业务规则只在一处判定：人员与材料的必填、长度、枚举合法性由领域对象自守；"仅受理失败可重新申请"这类状态机判定只出现在聚合内；出站适配器与基础设施不得硬编码业务状态判定。
- 一次外部交互的轨迹记录必须一始一终同事务落库，不得留下只有开始没有结束的残留。
- 跨进程消息载荷必须是两端共用的类型定义，不得靠字符串键名在两端各自维护；MQ 主题、绑定名与消费组名称全项目只有一处定义来源。
- 多租户接入的公共能力不得按租户复制：租户差异只允许出现在报文字段映射与校验规则，解析与流水线装配必须共用实现。
- 零引用即删除：无调用点的类、方法、枚举值、配置字段与 Maven 依赖一律删除；只有一个实现且无替换需求的接口不是扩展点，不得为假想需求保留抽象。
- 只读链路必须可定位：一次申请从网关进入起，同一链路标识必须能在服务日志、MQ 消费与异步任务日志中被检索到。
- 文档不得承诺不存在的验证：验收口径必须与实际存在的构建与脚本验证手段一致，禁止保留"测试全部通过"这类已失效的表述。

## 正常场景

1. 以 `--spring.profiles.active=prod` 启动应用，两个调度任务按配置间隔正常触发，服务健康检查通过。
2. 通过 `claim-gateway` 提交的租户A与租户B申请，响应逐字段与整改前一致，异步链路仍抵达 `WAIT_AUDIT` 且 Outbox 事件投递成功。
3. 以 `claim.mock.enabled=true` 且指向独立假件进程时，材料受理失败链路与重新申请链路行为与整改前一致。
4. 一次经网关的申请，用链路标识可 grep 出网关、应用、调度与消费方的全部相关日志。
5. `bash scripts/smoke/golden-path.sh` 在干净数据库上一次跑通并输出 PASS。

## 异常场景

| 场景 | 期望处理 |
|---|---|
| 外部系统地址未配置 | 启动失败，错误信息列出缺失的配置键名，不得回退为指向本服务 |
| 租户报文不是合法 JSON | 返回业务错误码，日志保留原始解析异常类型与申请号，不输出报文原文 |
| 状态机违例（如对非受理失败的申请重新提交） | 返回本域业务错误码与明确错误信息，不得返回 500 |
| 外部调用抛错或消息重投 | 交互轨迹不出现只有开始无结束的残留行 |
| 畸形 JSON、缺租户头、未支持租户 | 分别映射为既有业务错误码与协议不支持错误，与整改前一致 |
| MQ 主题在配置中新增但未在 broker 建好 | 静态检查脚本失败并指出缺失主题，不依赖运行期报错 |

## 边界条件

- 已落库的申请数据必须可读：不改变人员信息持久化 JSON、状态枚举值序列与表结构既有列语义，历史行由新代码正常还原。
- 删除模块不得影响存量对外路径：网关路由中仍存在指向已删模块的路径时，必须一并删除路由而非保留恒失败入口。
- 引入版本化迁移不得改动现有表结构语义，只做结构等价纳管；首次迁移在已有数据卷上必须幂等。
- 假件剥离后，本地联调仍必须能在不依赖真实外部系统的情况下跑通全部材料失败与承保超时场景。

## 本次范围

- 配置 profile 归属与假件开关、外部地址默认值。
- 出站客户端路径外置、解析异常原因保留。
- 交互轨迹事务边界。
- 领域不变式异常语义与业务异常/错误码体系合一。
- 必填校验与状态机判定单一化、租户接入实现去重、消息载荷与 MQ 名称收口、时间与 DO 映射风格统一。
- 死代码与零引用依赖删除；模块收敛与假件剥离。
- 数据层缺失索引、死表、逻辑删除与版本化迁移；环境变量命名体系一致化。
- 链路标识贯穿与运行指标暴露；固化黄金路径脚本与静态契约检查脚本。
- 受影响 Spec 与架构文档同步，历史空头验收口径修正。

## 验收标准

- 以 `prod` profile 启动成功，非 local 场景下不存在未解析的配置占位符。
- 未提供外部系统地址时启动失败并报出键名；`claim.mock.enabled` 未显式开启时假件接口不注册、不可访问。
- 状态机违例与租户报文解析失败均返回业务错误码，且异常保留 cause。
- 业务异常类型数与错误码枚举数各为 1，全部位于 `shared/contract`。
- 必填与状态机判定的重复实现点数量为 0；`tenants` 目录代码行数较整改前下降不少于 40%。
- 消息载荷字符串键名、MQ 主题与消费组字面量的非定义处引用数量为 0。
- 零引用依赖、零调用点的类/方法/枚举值删除后构建通过，`Asia/Shanghai` 字面量只出现 1 处。
- 后端 Maven 模块数为 3，`claim-foundation` 为单模块且不存在零类 artifact；生产 jar 内假件类数量为 0。
- 数据库结构变更走版本化迁移，已有数据卷上迁移幂等；两条 Outbox 查询的执行计划使用索引且无文件排序。
- 一次经网关申请的链路标识可跨同步、异步与调度日志检索；`metrics` 端点可访问。
- `scripts/smoke/golden-path.sh` 与 `scripts/check-contract.sh` 均通过，文档中直连应用端口而绕过网关的示例数量为 0。
- 全部历史 Spec 中失效的测试验收口径已修正，代码与文档逐条一致。
