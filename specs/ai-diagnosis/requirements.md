# AI 异常诊断需求

## 1. 定位

面向理赔业务异常的 Diagnosis Agent：基于 Application、Case 的运行证据自主调查，给出根因、影响判断和处置建议，并在授权范围内执行可逆处置。

Agent 只做调查、推理和 Tool 选择，不直接修改业务数据。

## 2. 触发方式

- **自动触发**：Application 或 Case 进入异常状态（受理失败、交付失败、回调超时、重试耗尽）时投递诊断事件。
- **人工触发**：运营在案件或申请详情页发起诊断，可附带补充说明。
- **批量触发**：对一段时间内同类异常发起批量诊断，用于发现共性根因。

同一业务对象短时间内重复触发时合并为一次诊断，避免重复消耗模型调用。

## 3. 调查能力

Agent 可自主查询以下实时业务数据：

- Application 状态、状态变更历史、参数校验结果
- Case 状态、当前阶段、阶段轨迹
- Application / Case 处理轨迹
- 外部调用记录（请求、响应、返回码、耗时）
- 回执记录与回调记录
- 重试与补偿记录
- 租户错误码定义
- 租户协议说明与字段映射

以下内容通过知识库检索：

- 租户协议文档
- 错误码手册
- 历史相似故障与处置记录

## 4. 调查循环

- 每轮输出：当前假设、待验证点、要调用的 Tool。
- 每轮结束后根据新增证据判断假设成立、被推翻或证据不足。
- 证据不足继续调查，证据充分形成结论。
- 达到最大调查轮次上限或置信度低于阈值时停止，转人工。

调查过程必须可回放：每轮的假设、Tool 调用、返回证据、判断结果都要落库。

## 5. 诊断结论

结论必须包含：

| 项 | 说明 |
| ------------ | ---------------------------------------------------- |
| Root Cause | 根因描述，必须关联实际证据 |
| Evidence | 支撑根因的证据列表，含来源、时间、摘要 |
| Impact | 影响的申请、案件、阶段和可能的业务后果 |
| Confidence | 置信度，低于阈值不给出自动处置建议 |
| Suggestion | 处置建议，区分自动与人工步骤 |
| Action Level | AUTO / APPROVAL / MANUAL |

无证据支撑的结论不允许输出为根因，只能标注为「待验证假设」。

## 6. 处置分级

| Action Level | 适用场景 | 处理方式 |
| ------------ | ---------------------------------------- | ------------------------ |
| AUTO | 只读查询、幂等且可逆的状态刷新、回执反查 | Agent 可直接执行 |
| APPROVAL | 有业务影响但可回滚，如案件补推、阶段重提 | 生成待办，人工确认后执行 |
| MANUAL | 高风险或不可逆操作 | 只输出诊断与建议，不提供执行入口 |

需要人工确认的操作：

- 案件补推
- 阶段重新提交
- 任何可能改变外部业务状态的重复执行

禁止由 Agent 执行的操作：

- 撤销业务申请
- 跳过或调换业务阶段
- 直接修改核心业务数据（Application / Case / 阶段记录）
- 绕过状态机强制修改状态
- 修改幂等键、重试次数等控制字段

## 7. 人工接管

- 置信度低于阈值、证据冲突、超出最大轮次时转人工，并保留完整调查记录。
- APPROVAL 类动作生成待确认任务，包含动作、影响范围、预期结果和回滚方式。
- 人工可驳回 Agent 的建议，驳回原因进入知识库用于后续改进。

## 8. 可审计

- 每次诊断记录触发来源、操作人、模型标识和提示词版本。
- 每次 Tool 调用记录入参、出参摘要、耗时和 traceId。
- 每次处置记录授权级别、审批人、执行结果。
- 诊断记录不可物理删除，保留周期按租户配置。

## 9. 非功能需求

- 单次自动诊断默认 8 轮上限，单轮 Tool 调用不超过 5 个。
- Tool 查询只读，且必须携带 tenantCode，禁止跨租户查询。
- Tool 查询失败不影响诊断继续，作为「证据缺失」记录。
- 诊断过程异步执行，人工触发的首包响应不超过 1s，结果通过轮询或推送获取。
- 模型调用失败、超时需降级为「证据汇总 + 规则建议」，不允许静默失败。
- 提示词、Tool 描述、知识库版本需要可追溯。

## 10. 不在本期范围

- 自动生成代码或修复方案
- 跨租户横向对比分析
- 业务规则自动调优
- 影像内容识别类诊断
